# 강의실 예약 시스템

프로젝트를 시작하기 전에 [docs/SETUP.md](docs/SETUP.md)를 먼저 읽으세요.

## 프로젝트 개요

- 한 줄 소개: 강의실의 빈 시간을 확인하고 예약·취소할 수 있는 웹 앱입니다.
- 누구를 위한 앱인가: 강의실을 이용하는 회원과 강의실·운영 시간을 관리하는 관리자입니다.
- 어떤 상황에서 쓰는가: 필요한 강의실과 날짜를 선택해 예약하고, 본인 예약과 이용·취소 이력을 확인할 때 사용합니다.

현재 최소 기능 제품(MVP)으로 구현했으며, 예약은 1시간 단위이고 모든 이용 시간은 한국 시간(KST)을 기준으로 합니다.

## 주요 기능

| 과제의 꼭 있어야 하는 기능 | 화면(프론트엔드) | API(백엔드) |
| --- | --- | --- |
| 1. 회원가입·로그인·내 정보 관리 | 이메일·닉네임·비밀번호 가입, 로그인·로그아웃, 닉네임·비밀번호 변경 | Supabase Auth 연동, 세션 처리, 닉네임 중복 검사, 서버 입력 검증 |
| 2. 강의실·요일별 운영 시간 관리 | 관리자 전용 강의실 등록·수정, 요일별 운영 시간·휴무 설정 | 관리자 권한 검사, 강의실·운영 시간 저장, 기존 예약과 충돌하는 운영 시간 변경 차단 |
| 3. 강의실 예약·조회·취소 | 강의실·날짜별 빈 시간 선택, 내 예약과 이용·취소 이력 조회 | 예약 확정, 중복 예약 방지, 소유권 검사, 시작 전 취소 |

백엔드는 Next.js Server Actions와 서버 조회 함수로 구성합니다.

더 만든 기능:

- 서비스 소개·이용 방법·주요 기능을 안내하는 홈 화면
- 로그인 상태와 관리자 여부에 따른 공통 메뉴
- 닉네임 정규화 및 영문 대소문자를 구분하지 않는 중복 검사
- 강의실과 예약 목록의 페이지 구분
- 예약 시작·종료 시각에 따른 예정·이용 중·지난 예약 구분
- 취소 이력 보존
- 동일 시간의 동시 예약 요청에 대한 DB 트랜잭션·행 잠금 처리

회원가입은 이메일 인증 메일 없이 바로 가입하는 방식입니다. 관리자는 일반 사용자와 같은 로그인 화면을 사용하며, 관리자 계정에만 강의실 관리 메뉴가 표시됩니다.

## 기술 스택

- 프론트엔드: Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4, React Hook Form, Zod
- 백엔드: Next.js Server Components·Server Actions·Proxy, Supabase Auth, Prisma 7, Node.js 24
- 데이터(어디에, 무엇을): Supabase PostgreSQL에 앱 회원 정보·역할, 강의실, 요일별 운영 시간, 예약·취소 이력을 저장합니다. 인증 계정과 비밀번호는 Supabase Auth에서 관리합니다.

앱 DB 조회·변경은 서버의 Prisma 연결을 사용합니다. 서버에서 로그인·역할·예약 소유권을 검사하며, 앱 테이블의 브라우저 직접 접근은 제한합니다.

## 실행 방법

1. Node.js 24를 준비하고 프로젝트 폴더에서 의존성을 설치합니다.

   ```bash
   npm ci
   ```

2. `.env.example`을 참고해 로컬 `.env`를 설정합니다.

   - `DATABASE_URL`: 앱 실행용 Supabase PostgreSQL 연결
   - `DIRECT_URL`: Prisma 마이그레이션용 연결
   - `NEXT_PUBLIC_SUPABASE_URL`: Supabase 프로젝트 URL
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: Supabase 공개 키

   실제 `.env`와 비밀값은 GitHub에 올리지 않습니다. DB 연결과 공개 CA 설정은 [Supabase 설정 안내](docs/SUPABASE_SETUP.md)를 따릅니다.

   새 DB를 사용할 경우 대상 환경과 마이그레이션을 검토한 뒤 적용합니다. 기존 개발 DB를 재사용한다면 이미 적용된 이력을 먼저 확인합니다.

   ```bash
   npm run db:migrate:deploy
   ```

   현재 가입 흐름은 Supabase의 Confirm email을 비활성화한 설정을 전제로 합니다. 관리자 역할은 일반 회원가입으로 부여되지 않으며, 대상 계정을 확인한 별도 관리 절차가 필요합니다.

3. 개발 서버를 실행하고 브라우저에서 접속합니다.

   ```bash
   npm run dev
   ```

   로컬 주소: http://localhost:3000

검사·빌드 명령:

```bash
npm run check
npm run db:validate
node --test tests/auth.test.mjs tests/classrooms.test.mjs tests/reservations.test.mjs
npm run build
```

`check`는 타입·린트·서식 검사이며 실제 DB 연결이나 기능 테스트를 대신하지 않습니다. `db:validate`는 Prisma 스키마 검사입니다.

배포 주소(있으면): https://nextjs-classroom-reservation.vercel.app

현재 배포는 기존 Supabase 개발·테스트 DB를 사용하는 테스트 배포입니다. GitHub `main` 브랜치와 Vercel이 연결되어 있으며, 해당 브랜치에 푸시하면 자동 배포가 실행됩니다.

배포 설정은 [Vercel 안내](docs/VERCEL_DEPLOYMENT.md)를 참고하세요. 일부 안내에는 보일러플레이트 초기 설명이 남아 있으므로, 현재 앱의 구현·검증 상태는 이 README와 작업 계획을 함께 확인하세요.

## AI 활용 내역

- 사용한 도구: Codex, 로컬 검사·테스트 도구, 브라우저 자동화 도구
- 주요 프롬프트(그대로 붙여 넣기):

  > 최소 mvp로 회원가입한 사용자는 관리자가 생성한 강의실들 중 선택되지 않은 시간을 선택시 예약이 완료되고 시작 시간 이전에는 취소할 수 있도록 만들고자 할 경우 어떻게 계획을 수립해야 하는가?

  > 운영시간은 요일별로 설정하고, 회원가입시 닉네임을 추가하고 사용자 정보에서 닉네임과 비밀번호 변경을 할 수 있도록 메뉴등을 추가할 수 있는가?

  > **Supabase DB + Auth:** 앞서 제시한 6번대로 인증 연동  을 진행하라.

- AI가 만든 것 / 사람이 고친 것: 사용자가 요구사항·범위·권한·DB 변경·배포를 결정하고 승인했습니다. Codex가 계획, DB 모델·마이그레이션, 서버 처리, 화면, 테스트와 문서를 작성했습니다. 사용자는 계정 생성·본인 확인·배포 앱 로그인 등 직접 조작이 필요한 단계를 수행했습니다.
- 결과를 확인한 방법:
  - 인증·강의실·예약 관련 자동 테스트 51개 통과
  - 타입·린트·서식 검사와 프로덕션 빌드 통과
  - 실제 개발 DB의 마이그레이션·스키마·접근 권한 확인
  - 실제 가입·로그인·닉네임 변경·중복 거부 확인
  - 관리자 강의실 등록·운영 시간 수정 확인
  - 실제 예약·중복 거부·취소·재예약 확인
  - 서로 다른 사용자의 예약 접근·취소 권한 검사
  - 실제 브라우저 HTTP 경로의 동시 요청에서 예약 성공 1건·중복 거부 1건 확인
  - 시간 경계·운영 시간 충돌 검증 후 테스트 트랜잭션 전체 롤백
  - 배포 앱에서 관리자 로그인·강의실·운영 시간·예약 가능 시간·예약 이력 조회 확인
  - 최근 홈 화면 변경의 검사·빌드·로컬 HTTP 내용·링크 확인

실제 DB 쓰기 검증은 승인된 개발 환경과 테스트 데이터로 수행했습니다. 모의 테스트·실제 DB 검증·브라우저 검증은 서로 구분했습니다.

## 팀원 역할

(이름·학번 없이 역할만)

- 기획: 사용자 요구사항과 MVP 범위 결정, AI와 함께 계획 검토
- 프론트엔드: AI 지원으로 홈·회원·관리자·예약 화면 구현
- 백엔드: AI 지원으로 인증 연동·권한 검사·DB·예약 처리 구현
- 검증: 자동 검사와 승인된 실제 환경 검증, 사용자의 직접 계정 조작 및 결과 확인

## 아쉬운 점과 다음에 할 일

- 앱 내 비밀번호 변경·변경 후 재로그인의 실제 화면 흐름은 아직 검증하지 못했습니다.
- 배포 환경에서 예약 생성·취소와 동시 요청 검증은 별도로 남아 있습니다. 로컬 검증 결과와 구분합니다.
- 최근 홈 화면은 브라우저 도구 시간 초과로 시각적 배치 검증을 완료하지 못했습니다.
- 홈 화면 변경의 Vercel 반영 여부는 해당 커밋의 배포 결과를 별도로 확인해야 합니다.
- 이메일 소유 확인과 분실 비밀번호 복구는 현재 MVP에 포함하지 않았습니다.
- 실제 서비스 전에는 개발·테스트 DB와 운영 환경을 분리하고 인증 정책·메일 발송·백업·운영 절차를 검토해야 합니다.
- 일부 보일러플레이트 문서와 현재 앱 사이에 설명 차이가 남아 있습니다. 문서별 승인 범위에서 정리할 필요가 있습니다.
